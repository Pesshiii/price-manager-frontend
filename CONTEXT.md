## Glossary

### Поставщик (Supplier)
Организация, поставляющая товары. Имеет только имя (`name`). Может быть привязана к фидам и маппингам фидов — удаление заблокировано (`409`), пока существуют связанные объекты.

### Фид (SupplierFeed)
Одна сессия загрузки прайс-листа от поставщика. Жизненный цикл: `draft` (загрузка файлов) → `processing` (Celery-задача матчинга) → `matched` (все строки сопоставлены автоматически) / `partial` (часть строк в MatchQueue) → `done` (очередь разобрана вручную), либо `error` при падении задачи. Содержит список `session_ids` загруженных файлов и записи (`SupplierFeedEntry`).

### MatchQueue
Виртуальная очередь — фильтр `SupplierFeedEntry` с `product=null, skipped=false`. Не отдельная модель. Пользователь разбирает записи вручную: подтверждает кандидата, ищет товар вручную, создаёт новый товар, пропускает запись или игнорирует SKU навсегда. После разбора последней записи фид автоматически переходит в `done`.

Доступные действия над записью:
- **Подтвердить** — привязать кандидата (`resolve/ {product_id}`), создаёт `SupplierLink`.
- **Найти вручную** — поиск по каталогу, затем подтвердить.
- **Создать товар** — создать новый `Product(status=draft)` прямо из записи (`create-product/ {sku, name}`), одновременно создаёт `SupplierLink` и закрывает запись.
- **Пропустить** — пометить запись как пропущенную в этой сессии (`resolve/ {skipped: true}`), без долгосрочного эффекта.
- **Игнорировать** — создать постоянный игнор-линк (`ignore/`), SKU поставщика будет автоматически пропускаться во всех будущих фидах без попадания в очередь.
- **Создать все оставшееся** — массовое действие (`bulk-create-products/ {name_column}`): создаёт `Product(status=draft)` + `SupplierLink` для каждой нерешённой записи за один запрос. Колонка для имени товара выбирается из `FeedMapping.identity_columns + variable_columns`, preselect из `FeedMapping.product_name_column`. Ошибочные записи (конфликт SKU, пустое поле) пропускаются и остаются в очереди. Если очередь опустела — фид переходит в `done`.

### Маппинг (FeedMapping)
Шаблон конфигурации, описывающий формат файлов конкретного поставщика. Ссылается на Dataframe-пайплайн, который применяется к каждому загружаемому файлу перед матчингом.

### Запись фида (SupplierFeedEntry)
Одна строка выгрузки внутри `SupplierFeed`. Поле `data` содержит объединение identity-колонок и variable-колонок из `FeedMapping` (оба набора попадают в запись). Поле `match_candidates` — топ-N кандидатов с полями `{product_id, score, name, sku, category, brand}`, денормализованными в момент матчинга.

### Ссылка (SupplierLink)
Постоянное соответствие `supplier_sku → Product`, накапливаемое из разрешённых записей фидов.

### Товар (Product)
Единица каталога с JSONB-характеристиками. Идентифицируется по `sku`.

### Характеристика (Characteristic)
Пара ключ-значение в JSONB-поле `Product.characteristics`. Тип определяется `CharacteristicType`.

### Тип характеристики (CharacteristicType)
Схема для значения характеристики: имя (ключ в JSONB), тип значения (`value_type`), единица измерения, список допустимых значений (`options`), привязка к категориям.
