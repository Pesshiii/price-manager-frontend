# Глоссарий предметной области — Price Manager Frontend

## Выгрузка (SupplierFeed)

**Выгрузка** — сессия приёма периодического файла от поставщика, содержащего изменяемые данные о товарах (цены, остатки и т.д.). Не путать с **Импортом** (`ImportJob`) — тот обновляет постоянные характеристики товара. Жизненный цикл: `draft → processing → matched | partial → done | error`. `matched` — все строки авто-матчнулись выше порога, финальный «успешный» статус без ручной работы. `partial` — часть строк попала в MatchQueue; переход `partial → done` происходит автоматически на бэкенде, когда последняя запись очереди разрешается (resolve).

**Конфигурация выгрузки (FeedMapping)** — постоянная настройка на одного поставщика: какая колонка является `supplier_sku`, какие — identity-поля (идентификация для эмбеддинга), какие — переменные поля (цена, остаток и т.д.), а также порог авто-матчинга. Создаётся один раз, переиспользуется для всех последующих выгрузок этого поставщика. Одна выгрузка может содержать несколько файлов: либо прайс-лист разбит на части (по категориям, регионам и т.д.), либо переменные данные разнесены по файлам (например, цены — в одном файле, остатки — в другом). Бэкенд объединяет все файлы при обработке.

**Identity-поля** — колонки строки выгрузки, используемые для построения эмбеддинга при матчинге. Значения колонок конкатенируются и передаются в ту же службу эмбеддинга (Ollama), что и для полнотекстового поиска по каталогу. Косинусное сходство считается против тех же продуктовых эмбеддингов. Не путать с `supplier_sku` — тот является ключом SupplierLink, identity-поля идут только в эмбеддинг.

**Переменные поля** — колонки строки выгрузки с изменяемыми данными (цена, остаток, склад и т.д.). Сохраняются **только** переменные колонки (`FeedMapping.variable_columns`) в `SupplierFeedEntry.data` с ключами, совпадающими с именами колонок в исходном файле. Identity-поля и `supplier_sku_column` в `data` не попадают. Данные **не копируются в Product**. Потребители (отчёты, витрины цен) читают их напрямую из Entry: «текущая цена товара X от поставщика Y» = Entry с `product=X` из выгрузок этого поставщика в статусе `done` или `matched`. Читать данные из незавершённой выгрузки (`partial`, `processing`) не следует. Все завершённые выгрузки пока считаются актуальными; механизм агрегации/архивирования запланирован на будущее.

## Очередь матчинга (MatchQueue)

**MatchQueue** — множество строк выгрузки, для которых автоматический матчинг не дал результата выше порога. Не отдельная модель — это фильтр `SupplierFeedEntry` с `product=None` и `skipped=False`. Разбирается пользователем вручную.

**SupplierFeedEntry** — одна строка из загруженного файла поставщика в рамках сессии выгрузки. До матчинга `product = null`. Содержит переменные поля в `data` и топ-N кандидатов на матчинг в `match_candidates`.

**Кандидат на матчинг** — товар из каталога с косинусным скором сходства, предложенный алгоритмом для конкретной строки выгрузки. Хранится в `SupplierFeedEntry.match_candidates: [{product_id, sku, score}]`. Количество кандидатов — фиксированная константа бэкенда (топ-N). Если ни один кандидат не достиг минимального порога сходства, список может быть пустым — строка всё равно попадает в MatchQueue.

**Resolve** — действие пользователя над записью MatchQueue: подтвердить кандидата (`product_id`) или пометить как пропущенную (`skipped=true`). `skipped=true` означает, что товара нет в каталоге или данные в строке некорректны — это постоянное решение, не «разобраться позже». После подтверждения кандидата создаётся или обновляется SupplierLink. Пропущенные записи SupplierLink не создают.

## Связи (SupplierLink)

**SupplierLink** — постоянная подтверждённая связь между артикулом поставщика (`supplier_sku`) и товаром в каталоге (`Product`). Ключ: `(supplier, supplier_sku)`. Создаётся при первом подтверждении матчинга (resolve). В последующих выгрузках используется для мгновенного авто-матча без повторного эмбеддинга. Исправить ошибочный SupplierLink во время обработки выгрузки нельзя — строка с известным `supplier_sku` сразу авто-матчится и не попадает в MatchQueue. Переназначение делается отдельно: `PATCH /supplier-feed/links/<id>/` (страница управления связями).

## Поставщик (Supplier)

**Поставщик (Supplier)** — контрагент, предоставляющий выгрузки. Простая сущность: `{id, name}`. Управляется через `/api/suppliers/`. Имеет собственный CRUD-экран (`SuppliersPage`, `SupplierDetailPage`); со страницы детали можно создавать выгрузки и управлять конфигурациями этого поставщика.
